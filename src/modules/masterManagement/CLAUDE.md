# masterManagement module

Super Admin's master data: every admin-editable list the app reads (moods, subjects, grades, task types, difficulty reasons, rewards, avatars, plans, …). **Role:** SUPER_ADMIN edits. Everyone else reads active items through lookup endpoints.

## Where it lives
| Frontend | Purpose |
|---|---|
| `pages/MasterDashboardPage.jsx` (`/admin/masters`) + `masterDashboard.css` (`mm-`) | Stat tiles and a table of every master with counts |
| `pages/MasterListPage.jsx`, `MasterFormPage.jsx` (`/admin/masters/:masterType`, `/create`, `/:id/edit`; registered **after** the dedicated routes in `routeConfig.js` because it is a catch-all) | **Generic engine** pages for any `master_types` row. `components/DynamicExtraFields.jsx` renders the type's `field_schema` extras; `IconField.jsx` handles emoji or uploaded icons; `GradeRangeFields.jsx`. |
| `pages/<area>/*ListPage.jsx` + `*FormPage.jsx` | **Dedicated masters** with a fixed shape: academic years, schools, regulation activities, reward activities, student rewards, subscription plans, discount codes, avatars, and curriculum (task types, subjects, topics, audio tracks, question types via `components/CurriculumMasterList.jsx`). Themes, sticky-note styles and stickers pages still exist but are unlisted and empty (see "Unused masters removed"). Regulation activity "Video, picture or sound link" (`mediaUrl`, any http(s) URL): Grade 6+ Focus > Exercises plays it beside the exercise - YouTube/Vimeo link or video file as a video, a picture, or a sound - and falls back to a built-in picture of the steps (student `focus/ExerciseMedia.jsx`). The activity's **category** puts it under a tile (Breathing, Grounding, Movement, Sound, Mindfulness, or its own name). |
| `components/masterPages.css` (`ms-`) | `.ms-form`: form card capped at 760px, two columns (one under 720px) |
| `services/*.service.js` | `masterGeneric.service.js` (`/admin/master/types`, `/admin/master/:type/items…`), plus `academic`, `billing`, `reward`, `regulation`, `appearance`, `curriculum`, `dashboard` |

**Backend:** `routes/admin.routes.js` → `/admin/master` → `routes/master.routes.js` (nests `masterGeneric`, `masterAcademic`, `masterBilling`, `masterReward`, `masterRegulation`, `masterAppearance`, `masterCurriculum` routes; `middlewares/resolveMasterType.middleware.js`) → matching controllers/services/repositories. Generic tables: `master_types` (code, `field_schema`) and `master_items` (name, code, icon, `extra` JSONB, `display_order`, `is_active`). Read side for other roles: `routes/masterLookup.routes.js` (`/lookups/:type`, `/lookups/difficulty-picker`, allowlist `services/masterLookup.service.js#LOOKUP_TYPES`), plus `/parent/lookups/master/:type`, `/teacher/lookups/*`, `/auth/lookups/master/:type`, `/onboarding/lookups/:type`.

## Rules - read before changing
- **New databases get the masters from migrations.** `seeders/masterData/masterData.json` is a snapshot of every dashboard master (plans and discount codes excluded). Migration 111 and `npm run db:seed:masters` load it idempotently: insert missing rows, update only rows nobody has edited, never delete. After changing masters that other environments need, run `npm run db:masters:export`. Databases that already ran 111 then need `db:seed:masters` or a new migration that calls `applyMasterData`. A dedicated master table added later goes into `TABLES` in `seeders/masterData/masterData.js`.
- **Unused masters removed (migration 115, 2026-10-06 user request).** A master is only listed and seeded if something outside Master Management reads it. Removed: generic Teacher Types, Priorities, Task / Assignment Status, Notification Types, States / Provinces, Time Zones (types + items deleted; `priorities` also left `LOOKUP_TYPES` and the unused frontend `listPriorities`), and the rows of Colour Themes, Sticky Note Styles and Stickers (off the dashboard in `masterDashboard.service.js#DEDICATED_MASTERS`, out of the loader's `TABLES`; the tables stay because `dashboard_preferences`/`sticky_notes` keep unused FK columns). The app uses constants for statuses and notification types, `CANADIAN_PROVINCES`, the device time zone, built-in accents, the note `tone`, and Student Rewards instead. They are out of the snapshot and of the old seeders (`20260910000001/2/4`); `seeders/masterData/retiredMasters.json` exists only for 115's down(). Before adding a new master, make sure a screen or service will read it.
- **Nothing the admin can edit is hardcoded elsewhere.** A new admin-managed list is a `master_types` row, seeded idempotently, with per-type fields in `field_schema` → `extra`. It only needs a dedicated table if it has real relations.
- `extra` is validated against the type's `field_schema` in `masterGeneric.service.js`, not in a static Joi schema.
- **Built-in rows can't be deleted (migration 114, 2026-10-06 user request).** Every master table has `is_system`; every row of the master data snapshot is built-in (the loader sets it on each row it inserts or matches, never copies it from the JSON, and pauses the `set_updated_at` trigger so the "untouched" test still works). Lists return `isSystem`; every list page hides the Delete icon when it is true (Edit and Activate/Deactivate stay); every delete service calls `utils/builtInRecord.js#assertDeletable` first → 409 "This record comes with the platform…". Rows the admin adds are deletable as before. Subscription plans and discount codes are not in the snapshot and have no flag. Test: `.claude/testing/functional/master-built-in.mjs` (private backend) and `scenarios/master-built-in.mjs` (mocked UI).
- **Delete vs deactivate:** delete is refused while a record is in use ("…deactivate it instead") via real FK checks. Deactivated items vanish from pickers but must still resolve for history (e.g. old check-ins show their mood). Activate/deactivate writes an audit row.
- **Non-admins read only through lookup endpoints with an allowlist.** Adding a type readable by students, parents or teachers means editing `LOOKUP_TYPES` (or the role's lookup route). Clients can't widen it.
- Cross-list links live in `extra` (e.g. difficulty reasons → support strategies, used by `/lookups/difficulty-picker`). Emotional States carry `code`, icon or uploaded icon, background colour and `extra.intensity_level` (drives check-in alerts).
- **School address (Canada Post format, migration 116):** `SchoolFormPage` uses `auth/components/AddressFields` with the school name as the preview's first line, and has the new `addressLine2` (department/floor/suite). The backend validates schools with the shared `validators/common.js#addressFields`, so Canadian school addresses are stored upper case without punctuation. The list's "City / province" column reads "TORONTO ON".
- **Schoolwork views (migration 112):** Subjects carry `extra.color` - the one colour a subject has everywhere (sticky notes, list, calendar, Home, teacher lists; a student may pick their own on top). Assignment Types carry an `icon` (the kind of own work), and curriculum **Task Types** have an `icon` column (the form's Icon field, shown in the list) for teacher work. **Personal Activity Categories** (`activity_categories`: Extracurricular, Personal / family, Social plans, Appointment, Other; `code` + icon + `extra.color`) label busy times on the full calendar; students and parents read them via `LOOKUP_TYPES`. 112 only fills empty values, so an admin's choices are never overwritten.
- **Subscription plans and discount codes (2026-10-08, `validators/masterBilling.validator.js` + `masterBilling.service.js`):** a plan's price is 0 (a free plan - families start it without a card) or at least 0.50 CAD (the smallest card charge); trial days 0-365 (a free trial for a family's first subscription only); child/parent limits 1+ or blank. A code is letters, numbers, `-` or `_` (stored upper case); a percentage can't go over 100 even when only the value is edited (checked against the code as it will be); usage limit and the new **Uses per family** (`maxRedemptionsPerUser`, default 1) are 1+ or blank; the expiry can't be before the start. The form sends days: the start counts from the start of that day where the parent is, the expiry lasts to the end of the picked day where the Super Admin is (`expiryInstant`), and the edit form shows it with `toDateInputValue` (slicing the UTC string showed the next day). Service rule failures answer 422 with the field, like Joi. See the `subscription` doc for what parents get.
- Uploaded icons and pictures go through private storage. The old file is deleted only after the DB write commits.
- A pre-existing bug fixed earlier: `masterAppearance.service#pickFields` didn't copy `name`. When adding fields to a dedicated master, check the service's field pick-list.
- UI conventions: compact `FilterBar`, icon row actions (edit/view accent, activate green, deactivate amber, delete red), `ConfirmationModal` for delete/deactivate, `.ms-form` two-column forms.

## Phase 1 gaps (2026-10-09)
- **Difficulty Reasons** have three more fields (migration 126): Short label (first screen), Order on the first screen, First reply. Set on the client's six.
- **Regulation Activities:** 13 built-in (migration 127 added physiological sigh, belly breathing, sensory grounding, body scan, progressive muscle relaxation, guided imagery, self-compassion break).
- **Assignment Types:** Exam Preparation, Research, Other and Practice switched off (migration 128; own work moved to Test or quiz preparation / Research assignment / Other / custom task), list in the client's order. Task Types' nine older rows were already off.
